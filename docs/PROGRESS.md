## 二、未完成功能 ❌

### P0 - 核心功能（客户需求明确要求）

#### 1. NL2SQL 自然语言查询

- **客户需求原文**：`企业智能助手 → NL2SQL实现：针对上述数据表开发自然语言转SQL功能，支持员工通过口语（如"帮我查一下张三的最近跟进记录"）直接调取数据库信息。`
- **当前状态**：✅ 已完成
- **实现**：`dbman` 工具（`app/agent/tools/dbman.py`），基于 LLM 的 NL2SQL 引擎 + SQL 安全校验层 + 执行器。按角色控制表权限（employee 14张 / student 10张 / guest 4张）。

#### 2. 活动报名闭环

- **客户需求原文**：`客服Agent → 活动与讲座报名：支持客户查询近期的线上/线下留学分享会、招生官见面会，并直接完成活动预约与报名，有效沉淀私域流量。`
- **客户需求原文（详细拆解）**：`建立结构化的课程项目表与近期讲座活动表，包含时间、地点、报名方式等字段，支撑精准推荐与报名功能。` + `设计活动表，开发活动查询与报名接口，支持客户在对话中直接完成留学分享会或见面会的预约，并将报名信息自动录入后台系统。`
- **当前状态**：`Event` 和 `Registration` 表已存在，`db_query` 可操作，但前端无活动展示/报名UI，用户无法直接交互
- **差距**：需前端活动列表展示 + 报名交互 + Agent主动推荐逻辑

#### 3. 审批闭环 + 通知机制

- **客户需求原文（学生助手）**：`行政服务：支持学生在线提交请假申请，系统自动推送至班主任，并支持通过企业智能助手实现移动端在线审批，形成完整的请假闭环。`
- **客户需求原文（学生助手）**：`售后反馈：支持在线投诉与建议提交，自动生成工单存入反馈表。老师跟进处理完毕后，系统自动向学生同步"您的xxx投诉已解决"的反馈通知。`
- **客户需求原文（学生助手-详细拆解）**：`打通"学生提交-写入数据表-推送班主任-在线审批-回调通知"的全链路。`
- **当前状态**：`LeaveRequest` 和 `Complaint` 表支持CRUD操作，但无消息推送机制，无审批回调通知
- **差距**：需实现消息推送（WebSocket/SSE/邮件）+ 审批状态变更通知

#### 4. 智能报告生成（5种报告）

- **客户需求原文**：`智能报告 → 1.全域客户经营分析报告 2.员工日报汇总报告（日） 3.员工日报汇总报告（周） 4.学生心理健康周报 5.投诉处理周报`

##### 4.1 全域客户经营分析报告

- **客户需求原文（详细拆解）**：`全面覆盖意向、成交及流失三大核心客群。针对意向客户，重点统计新增数量及同环比趋势，并通过特征聚类精准提炼共性画像；针对成交客户，深度复盘其转化路径与高价值特征；针对流失客户，智能归因并预警流失风险。最终通过多维度的AI洞察，为业务团队提供从精准获客、高效转化到流失挽回的全链路决策支持。`
- **当前状态**：完全未实现
- **涉及表**：Lead, LeadFollowUp, Registration

##### 4.2 员工日报汇总报告（日/周）

- **客户需求原文（详细拆解）**：`通过日、周等多维时间粒度，对全员提交的工作内容进行自动化梳理与提炼。系统利用AI智能提取日报中的核心进展、关键产出及潜在风险，将碎片化的日常记录转化为结构化的工作简报。`
- **当前状态**：完全未实现
- **涉及表**：DailyReport

##### 4.3 学生心理健康周报

- **客户需求原文（详细拆解）**：`基于留学生的日常情绪打卡、学业压力反馈及跨文化适应情况，利用AI智能汇总本周整体心理态势，精准识别存在孤独感、学业焦虑或文化冲突等潜在风险的学生群体。同时，系统会结合留学周期的特殊节点（如考试周、假期），生成情绪波动趋势分析，并智能推荐个性化的心理疏导方案与社群支持建议。`
- **当前状态**：完全未实现
- **涉及表**：PsychologyProfile, PsychologyWarning, ExamSchedule

##### 4.4 投诉处理周报

- **客户需求原文（详细拆解）**：`通过全流程的数据追踪，提升海外留学服务的售后质量与响应效率。报告不仅实时汇总本周的投诉总量及其同环比变化，还会利用AI对投诉内容进行智能分类。系统会重点追踪每一笔投诉的跟进状态、处理时效及最终满意度，自动识别长期未决的疑难案件并触发预警。`
- **当前状态**：完全未实现
- **涉及表**：Complaint
